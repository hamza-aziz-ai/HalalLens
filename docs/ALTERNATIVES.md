# ALTERNATIVES

What we turned down, why, and what would change our mind. Decisions that chose between these are in [DECISIONS.md](DECISIONS.md).

| Choice          | Rejected option                                                                | Why rejected                                                                                                                                                                                      | Revisit if                                                                          |
|-----------------|--------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------|
| Verdict states  | A fourth numeric "borderline" state                                            | Closeness to a cap does not change `<=` semantics; `needs-review` already covers data quality                                                                                                     | A scholar defines a review band                                                     |
| Required ratios | Only debt, cash and income required                                            | Methodology change smuggled into a bug fix; SS21 does not back the two extra gates either way                                                                                                     | Scholar-approved methodology                                                        |
| Float tolerance | Epsilon (e.g. 1e-9) around thresholds                                          | An undocumented tolerance can flip a real failure to a pass; exact Decimal has no tolerance                                                                                                       | Never for decisions                                                                 |
| LLM prose       | Bypass the LLM entirely (D-004), or a keyword/polarity guard presented as safe | Bypass removed a feature the maintainer wanted; any keyword guard passes some paraphrases (Codex's counterexamples). Chosen: keep the mode, call the guard best-effort, add the UI caveat (D-010) | Per-claim validation against ratio facts exists                                     |
| Quality overlay | Mask only on read, or block only an allowlist of issue types (D-027)           | Read-only masking leaves conclusive stored rows for alerts and later readers; an allowlist lets a new issue type through silently                                                                  | Some issue type is agreed to be advisory, not blocking                              |
| Legacy rows     | A quarantine flag / schema field to hide unrecomputed results                  | Needs a migration; a controlled cutover (recompute in the maintenance window) gives the same safety                                                                                               | Cutover cannot be done atomically                                                   |
| Registry        | Docker Hub as primary                                                          | Needs a stored token and has pull limits; GHCR uses the built-in token                                                                                                                            | The user wants Docker Hub discoverability (mirror on release tags)                  |
| Releases        | semantic-release; manual tags                                                  | semantic-release needs more secrets; manual tags get forgotten                                                                                                                                    | Release volume grows                                                                |
| Dependency bots | Renovate                                                                       | One more app to trust; Dependabot is already present                                                                                                                                              | Grouping needs outgrow Dependabot                                                   |
| Auto-merge      | Every PR auto-merges with CI as the only gate, no exclusions                   | A PR can change its own gate (workflows, tests); auth, billing and verdict code merge unread (D-015 revision)                                                                                     | Sensitive changes merge without a human; a weakened test passes CI                  |
| Deploy          | Watchtower pull-based auto-deploy                                              | No approval gate or migration ordering on a billing app                                                                                                                                           | Never without a gate                                                                |
| Pages vs VM     | GitHub Pages as the canonical UI                                               | Its build set no API URL; the maintainer chose the Docker deployment (D-011) and removed the Pages workflow on 2026-10-28                                                                         | A static demo with a public API or a mock mode becomes useful                       |
| Backfill        | Reuse the plain `jobs.backfill_evaluations` for history                        | It skips rows with ratios (after the `has_ratios` fix), reads a 500-row window and re-enriches from the vendor                                                                                    | n/a: its `--recompute` mode repairs history from the current stored inputs and caps |
| Plan switching  | `next_plan` columns on users (one queued period); stored per-purchase boundaries rewritten on refunds | One slot blocks concurrent checkouts; rewriting boundaries on every refund is where history gets corrupted (D-024) | Plans differ in features, or auto-renewal needs provider-held periods |
| Auto-renewal    | Razorpay Subscriptions (UPI Autopay, e-mandates) now                           | Mandates, failed-debit handling and cancellation are a separate project; the ledger accepts each charge as a grant later                                                                         | The maintainer wants renewals without a manual payment                              |
| README layout   | One long README with the diagrams added; a generated docs site (MkDocs)        | A long README buries the two diagrams; a docs site adds a build, a dependency and hosting for a handful of pages (D-026)                                                                          | The guides need search or versioned docs                                            |
| Postgres upgrade | `pg_upgrade` (copy or `--link`) for 14 -> 17                                 | Needs both majors' binaries in one container (the official images ship one); for 21 MB a dump and restore is minutes and leaves the old volume as the rollback (D-029)                         | The database is too large for a dump and restore window                               |
| Postgres upgrade | Bump the image in place on the same volume                                     | 17 refuses a 14 data directory; there would be no untouched copy to roll back to (D-029)                                                                                                         | Never for a major version                                                             |
| Postgres upgrade | Logical replication 14 -> 17, then switch over                                 | Near-zero downtime, but publications, subscriptions, sequence sync and a cutover for 21 MB and a few minutes of maintenance (D-029)                                                              | Downtime becomes unacceptable or the data is large                                    |
| Postgres upgrade | A reusable upgrade script and a CI upgrade drill now                           | Deferred: one manual upgrade with a written runbook and a local rehearsal; a script tested once a year rots (D-029)                                                                              | The next major upgrade, or upgrades become routine                                    |
| Input mappings  | A liquid-assets composition formula (cash + current investments + receivables); keeping the stand-ins and flagging verdicts | A formula is a methodology choice, not a bug fix, and belongs to D-023's reviewed mapping; flagged verdicts still publish known-wrong numbers (D-028) | A scholar approves a composition, or D-023 confirms per-filing facts |
| Upgrade credit  | Refund the unused timed time when Lifetime is bought                            | Moves money twice (refund out, payment in), each with its own failure and reconciliation path; the maintainer chose a discount (D-030) | Razorpay or an accountant requires refunds instead of discounts |
| Upgrade credit  | Claw back or suspend Lifetime when a credited payment is refunded later         | Maintainer decision: alert only; an automatic suspension would punish a buyer for a refund the operator made (D-030) | `credit_conflict` items show up in practice |
| Upgrade credit  | Price by settlement (capture) time instead of the attempt's creation time       | A UPI or bank flow started inside the window and captured later would be refunded; the attempt's `created_at` comes from Razorpay, so the buyer cannot stretch it (D-030) | Razorpay stops reporting `created_at` on the payment entity |
| Upgrade credit  | Credit from pre-ledger (legacy) grants                                          | Their funding payment and amount are not proven until D-025 binds them (D-030) | Legacy grants are bound to verified payments |
| Alert emails    | An outbox table (one row per alert to send)                                    | A second table that can outlive or duplicate its watch row; the mailbox on the watch row says the same with two columns, and a verdict that flips back leaves nothing to send (D-031) | Alerts need history, several channels, or digests                                    |
| Alert emails    | Send from `/alerts/check` (the old operator path, moved to the subscriber)     | Mail only when someone calls the route; a request thread doing SMTP; no retry or fairness (D-031)                                                                                              | n/a                                                                                  |
| Alert emails    | One-click unsubscribe token, `List-Unsubscribe` and RFC 8058 now               | A new bearer token, a public route and header handling for a pilot with a handful of subscribers; the account-page opt-out covers it (D-031)                                                   | Volume or a mail provider's bulk-sender rules require it                             |
