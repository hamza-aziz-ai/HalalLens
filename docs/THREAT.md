# THREAT

Who could behave badly, what they can reach, and what stops them. **Known gaps are listed honestly.**

| Actor / entry point                                                  | Worst realistic abuse                                                                           | Mitigation today                                                                                                                                                 | Gap                                                                                                              |
|----------------------------------------------------------------------|-------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------|------------------------------------------------------------------------------------------------------------------|
| Anonymous visitor -> `/halal-score`                                  | Free compute, scrape, send odd numbers (booleans, NaN, `"1e-400"`) to force a false `compliant` | Per-IP rate limit; Pydantic `extra="forbid"`; booleans and unusable strings rejected; engine rejects non-finite, negative, out-of-range                          | Limiter is per process; numeric JSON literals that underflow before validation                                   |
| Anonymous -> `/auth/*`, `/billing/plans`                             | Credential stuffing, trial farming                                                              | Per-IP login/register limits; PBKDF2 600k; hashed opaque tokens                                                                                                  | Counters reset on restart                                                                                        |
| Anonymous -> `/auth/*` (account takeover) | Pre-register a victim's or an admin's address with a known password; ride the victim's later Google sign-in; claim admin by typing an `ADMIN_EMAILS` address | Email-first sign-up (password chosen only after the mailbox is proven); Google matched by subject, never by email, `email_verified` must be `true`; admin only on proof; sessions require a verified email; reset revokes all sessions under the same row lock as login (D-020) | Email delivery is a dependency: no SMTP, no password accounts. Google flows are single-use and bound to the starting browser by an HttpOnly cookie; linking needs the password and the starting session (D-021) |
| Logged-in free user                                                  | Reach paid routes, other users' watchlists                                                      | Tier checks on every route; watchlists keyed off the session, `user_id` in the path ignored                                                                      | None known for watchlists since D-019 (Postgres, conditional updates)                                |
| Signed-in user                                                       | Spend vendor quota via `/market-data` or paid `?refresh=true` lookups                          | `/market-data` requires a session; per-user metered limit; hard monthly cap `INDIAN_API_MONTHLY_LIMIT` (450 in production compose) counted across restarts      | Cost monitoring absent; one user can exhaust the shared monthly cap                                              |
| Razorpay webhook sender                                              | Forge or replay a payment event                                                                 | HMAC signature check; idempotent on `(provider, event_id)`; grants need a captured payment matching the order's amount and currency                              | Live-key separation and secret rotation are the operator's job                                                   |
| Buyer gaming refunds or purchases                                    | Refund a second payment to revoke a plan; race checkouts for extra time; get access for an uncaptured or under-paid payment | Refunds apply only to the payment that funded the order, summed per refund id; one locked transaction per settlement; captured-and-matching check (D-024, D-025) | Refund policy itself (refund after use) is the merchant's decision, not code |
| Automatic refunds (reconciler)                                       | Refund the payment that actually funded access; refund twice                                     | Eligibility re-checked under the order lock (funding payment known and different); one immutable request per payment with an idempotency key; TEST keys only | Going live needs a reviewed change |
| Anyone -> `/health/billing`                                          | Learn internal state                                                                            | Returns only a status and an age; read-only; no-store                                                                                                            | None known |
| Admin / insider                                                      | Edit governance overrides that rewrite every user's verdict; read feedback                      | Admin-only routes; reviewer identity from the session; overrides stored and surfaced                                                                             | No four-eyes review on overrides                                                                                 |
| Malicious or malformed filing (PDF/XBRL)                             | Parser crash, mis-scaled values, injected numbers                                               | Parsers run in the ETL, values pass `coerce_amount` and engine validation                                                                                        | The extraction regex for prohibited income also matches "interest income"; `liquid_assets` is mapped from "current assets" (`_detect_scale` matches whole unit words since #158) |
| Vendor API (Indian Stock API)                                        | Wrong or hostile numbers; outage                                                                | Values validated; Bhavcopy fallback; failures recorded                                                                                                           | "Other, Net" mapped as prohibited income (the payload cache keeps successes for 6 h and no failures since #156)  |
| Compromised dependency                                               | Supply-chain code execution                                                                     | Lockfile hashes, Dependabot, gitleaks, SHA-pinned Actions, 47 runtime packages (was 103)                                                                         | Published images carry an SBOM and provenance (D-018) but are not signed; Python bumps are manual                |
| Leaked secret (public repo)                                          | Account or key misuse                                                                           | History was purged and keys were rotated by the maintainer; gitleaks runs on every PR                                                                            | Anyone who cloned before the purge still holds old history; GitHub caches and `refs/pull/*` may keep it          |
| LLM prompt injection / hallucination (only when `NARRATOR_MODE=llm`) | Poisoned filing text or model error steers the explanation                                      | Model asked only about conclusive verdicts; must repeat the engine's verdict; text passes a keyword guard; label is the engine's; UI marks LLM text AI-generated | **Best-effort only**: a paraphrase the guard does not know can still contradict the verdict                      |
