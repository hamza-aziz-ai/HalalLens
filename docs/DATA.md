## Trade-offs worth defending
- **`(symbol, filing_date)` as the key** keeps one evaluation per filing, so a recompute overwrites in place. That is why history cannot be audited unless the `--recompute` run (PR #91) writes its before/after CSV report first.
- **Verdict in two columns** (`is_compliant` boolean and `verdict` text): the boolean stays for old consumers and is `NULL` for unknown; the text carries the full state (`compliant`, `non-compliant`, `insufficient-data`, `needs-review`).
- **Watchlists in Postgres** (D-019) replaced the file store, so several API workers or hosts no longer lose updates.
- **Access as a fold over grants** instead of a stored renewal date: a queued purchase or a refund never rewrites another purchase's dates, and there is no promotion job (D-024).
- **Ratios as JSONB** keep each evaluation self-describing (value, threshold, passed, note, provider).
